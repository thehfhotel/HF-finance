# kbiz-bot

Browser-automation companion to the payroll-form app. Logs into K BIZ
(KBank Business Online), scrapes the registered-payroll-account list,
and uploads beneficiary xlsx files generated by the main app.

Headful only — every script opens a real Chromium window.

## First-time setup

```sh
cd kbiz-bot
bun install
bunx playwright install chromium
cp .env.example .env
# edit .env with KBIZ_USERNAME / KBIZ_PASSWORD
```

## Scripts

```sh
npm run login        # warm up / verify the persistent browser profile
npm run verify       # quick check the session is still alive
npm run list         # scrape the registered-payroll-account list
                     # writes ../data/kbiz-registered.json
npm run add-payroll -- <path/to/.xlsx>
                     # uploads beneficiary xlsx; auto-clicks Confirm and
                     # waits for the phone-app approval
npm run add-payroll -- <file> --observe
                     # like above but stops at the review popup so you
                     # can inspect entries before committing
```

## Session model

All scripts go through `src/lib/session.ts`:
- `withSession(fn)` opens a Chromium **persistent context** rooted at
  `browser-data/`. The same browser profile is reused across every
  script — KBIZ sees one continuous browser, no
  "signed-in-on-another-device" cascades.
- `ensureLoggedIn(page)` is idempotent: navigates to the dashboard,
  returns immediately if already authenticated, otherwise runs the
  login flow.

Don't run two scripts concurrently — they would deadlock on
Chromium's user-data-dir lock. Run one at a time.

## DRY mobile-approval helper

`src/wait.ts` exports `waitForMobileConfirmation({ reason, until, timeoutMs })`
which races a caller-supplied success Promise against a timeout (default
3 min) while printing a Thai heartbeat to stdout. Used in the
post-Confirm step of the add-payroll flow; reuse for transfer / batch
confirmation flows that still need a phone tap.
